# 本期需求与原型确认说明

## 1. 目标与边界

本期：商品下单、支付、积分、优惠券、个人中心及配套登录。原型已确认，下一阶段为**前端静态页面及模拟交互**，之后再安排接口开发和联调。

保持现有首页、搜索和商品详情交互，不重新设计一套商品浏览流程。原始 PDF 中其余模块暂缓。

## 2. 页面与已确认交互

### 首页、分类、搜索

- 首页沿用现有“搜索 → 宣传图 → 横向分类切换 → 双列商品列表”。既有数据、素材和交互以当前代码为准。
- 底部三个入口：首页、产品分类、我的。
- 产品分类是独立页面：分类选择与对应商品列表，不得与首页共用同一份展示内容，不重复首页宣传区。
- 原型分类采用左侧分类、右侧商品列表；分类名称及商品为示例。
- 搜索商品关键词、点击列表进入对应详情，返回时保留必要筛选状态。
- 购物车入口独立于底部三个 Tab。

### 商品详情

- 沿用当前轮播图、商品名与价格、商家说亮点、套餐、出游人群、价格日历、材料清单、商品图文。
- 保留行程说明、费用说明、退改规则、预订须知切换；PDF 要求各项可配置隐藏，静态阶段预留字段。
- 新增购买人数、加入购物车、立即购买及购物车入口。
- 商品、套餐、人群、日期、数量必须带入购物车与结算，不得全都指向同一演示商品。

### 购物车与确认订单

- 购物车支持勾选、全选、数量调整、删除和结算。
- 确认订单每项展示：**封面、商品名、套餐、人群、日期、数量**。
- **出行人必须归属具体商品明细**，按“商品 + 套餐 + 人群 + 日期”区分；不能仅在订单层面放一份共享名单。
- 每张商品卡片下有独立填写入口，显示需填写人数、已填人数、姓名和护照尾号。
- 填写页面明确展示正在填写的商品信息与封面，字段为姓名、护照号码、生日。
- 同商品不同套餐／日期也分别填写；购物车排序变化不改变归属；增加人数要补齐；其他商品的名单不算该商品已填写。
- 提交时逐商品验证，并将出行人按商品明细保存至订单快照；订单详情仍能查看对应关系。
- 出行人模块按商品配置决定是否展示。当前演示商品均需要填写，正式静态数据结构需支持不需要出行人的商品。
- 收货地址按需要选择，用于护照或材料邮寄。
- 金额展示商品原价总额、多人优惠、优惠券、积分抵扣、实付。
- 正式金额、库存、优惠资格以服务端为准；静态阶段使用模拟数据与统一演示计价。

### 支付与订单

- 展示待付款、办理中、已完成、售后退款，以及取消订单状态。
- 支持模拟成功、取消、失败；取消支付后可继续付款。
- 待付款可取消；支付成功进入订单详情或个人中心。
- 订单详情展示商品及出行人、订单号、价格明细和当前状态。
- 办理中进度及快递信息沿用既有体系，暂不开发新的进度管理引擎。
- 退款原型展示整单申请、原因、补充说明、审核中状态；超半年拒绝在线申请（期限起算点待定）。
- 不把支付按钮点击成功等同于正式支付成功；真实支付结果与退款结果必须由后端确认。

### 积分与优惠券

- 积分余额、兑换说明、收入／支出明细、下单抵扣入口。
- 文档明确：500 积分 = 10 元，永久有效；交易完成后消费 1 元得 1 积分，零头四舍五入；后台增减；退款时返还已用积分。
- 优惠券未使用／已使用／已过期列表，过期仍显示；一单一张，允许叠加积分；后台增减；退款后退回券。
- 首次授权手机号且完成验证绑定后满足 10 元新人券条件，发放应幂等。
- 推荐奖励来自 PDF，但本期转介绍页面、拉新及关系建立流程暂缓，不因积分模块自动纳入。

### 个人中心与登录

- 未登录态及已登录态、订单分类入口、积分、优惠券、收货地址管理、我司地图定位。
- 2026-09-16 页面设计调整：服务列表不再展示“个人资料”，改为“我司地图定位”；顶部用户区保留归档原型的资料编辑路径，头像昵称自愿完善。
- 我司地图定位为独立页面，游客可访问；展示公司名称、详细地址及地图位置，并支持打开地图导航。当前缺少已确认的公司地址与坐标，设计稿展示待配置状态，不虚构地点。
- 所有入口按归档原型进入完整页面，保留返回、筛选和按需登录恢复路径，不以说明弹窗代替订单、积分、优惠券、地址等页面。
- HTML 统一采用 750px 设计宽度，尺寸按 1px 对应 1rpx 转换；窄屏仅等比缩放画布。图标采用青绿细线轮廓与橙色内线点缀。
- 地址原型目前为单地址示意；前端静态开发需支持地址列表、新增、编辑、删除及默认地址，按 PDF 的地址管理要求补齐。
- 登录仅保留“手机号快捷登录”和“暂不登录，继续浏览”。用户已明确删除“微信登录，暂不授权手机号”备用入口。
- 允许游客浏览、搜索、查看详情及选择商品；结算或查看个人业务数据时按需登录。
- 协议默认未勾选；商户协议同意与微信隐私授权分开处理；拒绝可退出或主动重试。
- 原生手机号授权面板用交互示意表达；头像昵称自愿完善。
- 成功登录后返回原操作页面并保留所选商品及已填写信息，不自动提交或支付。
- 详见 LOGIN.md。微信底层 wx.login 仍需要，但不是额外的可见登录入口。

## 4. 暂缓事项

预约时间展示／同步、办理周期测算、首页额外模块、转介绍海报与好友列表、智能客服与消息体系、公司介绍扩展（基础地图定位已纳入）、签证进度体系改造、材料审核新功能，以及与本期交易无关的后台扩展。

后台商品配置、改价、积分券管理、退款会在后续接口阶段作为交易配套评估；本次不展开实现。

## 5. 静态开发验收重点

1. 原有首页与商品详情交互保留；分类页与首页明确不同。
2. 登录成功／拒绝／取消／失败及返回业务路径完整，游客态不显示私人信息。
3. 单商品、多个商品、同商品不同规格结算均可操作，封面可见，出行人归属准确。
4. 修改数量、删除与排序不会使出行人串商品；表单验证反馈明确。
5. 优惠选择与展示金额一致；模拟支付状态、订单列表及退款展示一致。
6. 个人中心、积分、券、地址、地图定位页面可以往返，空状态可用；顶部资料页保留原型已有交互。
7. 微信目标构建检查及适当的交互验证，说明遗留基线错误；不引入真实支付或注册动作。
8. 后续图片使用占位符或已有素材，不再为原型专门生成图片。

## 6. 已验证及未验证

原型通过脚本验证：页面导航、商品筛选、搜索、套餐／人群／日期传递、购物车与计价、出行人分组及数量校验、订单快照、模拟支付退款、登录与授权状态分支。最近修改中已移除备用微信身份登录入口并验证主要流程。

尚未完成：微信真机测试、真实 API／手机号／支付联调、微信合规审核。此前本地浏览器预览受环境策略限制，不能声称原型已完成视觉验收。原型是交互参照，不应原样复制其模拟状态为正式业务实现。
