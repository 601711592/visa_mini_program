## 3. 实现中补充的细则

PDF 未写到，开发时定下的规则：

- 出行人归属到具体商品明细（商品 + 套餐 + 人群 + 日期），不在订单层面共享一份名单。同商品不同套餐或日期分别填写；增加人数要补齐；按明细逐项校验，并保存到订单快照。字段为中文姓名、护照号、生日，商品可配置为不需要出行人。
- 下单时邮寄地址必填。
- 游客可浏览、搜索、查看详情和选择商品；结算和个人数据按需登录，登录后返回原页面并保留已选商品和已填信息，不自动提交或支付。
- 金额、库存、优惠资格和支付结果一律以服务端为准，前端点击结果不代表支付成功。

## 4. PDF 易误读处

- **积分抵扣上限**（第 6 页）：正文“上限为商品原价的 8 折”和图中“最高可抵商品价 20%”是同一条规则，即最多抵扣原价的 20%，两者不冲突。当前实现按原价计算上限，比例由后台配置。
- **订单按钮**（第 5 页）：办理中显示【查看进度】；待付款不显示进度和退款按钮（取消订单、继续付款不受影响）；**只有已完成的订单显示【申请退款】**，超过半年弹窗提示无法申请。
- **退款包括商家主动退款**（第 5 页），用于处理僵尸单和恶意订单，不只是用户申请。
- **未产生的抵扣项不展示**（第 3 页图中批注）。当前结算页和订单详情会显示 0 元的多人优惠、优惠券、积分行，与此不符。README 2026-09-20 曾在静态版实现隐藏，接入真实报价后没有保留。
- **搜索范围**（第 1 页）：包括商品标题，以及笔记标题和笔记内容。
- **购物车入口**（第 1 页）：带未结算数量角标。
- **订单状态名称**：个人中心写“服务中”，订单页写“办理中”，PDF 前后不一致；代码统一用“办理中”。
- **优惠券页的“推荐他人消费…获得同等积分”**（第 7 页）是从积分页复制过来的文字，按第 6 页的积分规则理解。
