# 手机号登录开发交付

2026-09-17。前后端真实登录代码已实现；真实授权、业务数据库迁移和生产发布未执行。

## 已实现

- 首页导航右侧“我的”进入账号页，支持游客态、校验中、手机号脱敏展示、退出登录。此页仅承接登录，不冒充完整商城个人中心。
- 独立登录页使用已确认插图与浅蓝样式；协议默认不勾选，仅支持手机号快捷登录或继续浏览。
- 微信原生 `getPhoneNumber`、隐私回调与 `agreePrivacyAuthorization` 衔接；拒绝及页面离开会结束等待回调。正式隐私指引由 `openPrivacyContract` 打开；不支持所需能力时提示更新微信。
- 正式服务协议由后端读取，未配置时显示失败和重试，不以内置原型文本注册。版本变更时重新加载并清除勾选。
- token 按小程序和接口环境隔离；旧裸 token/userInfo 不直接复用。启动校验业务会话、单独检查微信会话，不再以本地 token 存在认定登录。
- 请求超时/网络失败均结束 Promise。401 清理对应会话，403 不自动登录，不自动重放业务写操作。
- 登录成功返回来源或指定目标；恢复已有页面实例时保留选择。不自动提交订单或支付。
- 敏感草稿仅在内存保存：会话失效隐藏，同一会员登录后恢复，换账号或退出清理。迟到请求不得覆盖新会话或取消后的状态。
- 后端会员、会话、首次绑定资格都按小程序独立。手机号冲突不自动合并、不自动换绑。新人券只记录待发资格，不显示已到账。

## 后续业务页面接入

登录服务位置：`src/store/global.ts`；敏感草稿：`src/utils/auth-drafts.ts`。

```ts
const global = useGlobalStore();
// 在需要读取个人数据的入口调用。false 表示已转登录页或未完成登录，立即终止原操作。
if (!(await global.ensureLogin({ target: '/pages/account/index' }))) return;
// 仅继续当前用户主动发起的读取操作。
```

- `target` 是已注册的站内页面，可包含非敏感查询参数；原生 Tab 页面传 `mode: 'switchTab'`。没有 target 时返回发起页面。
- 登录页不保存业务执行函数；成功只恢复页面，原页面按需要重新加载数据。提交订单/付款仍需用户再次主动操作。
- 用 `saveSensitiveDraft(itemKey, value)`、`readSensitiveDraft<T>(itemKey)` 管理草稿。itemKey 应对应稳定商品明细 ID，不能只用列表下标；商品选择本身由业务模块保留。
- 不要把出行人、手机号或地址写入 URL、普通持久化缓存或另一个未注册清理的 store。长期敏感数据需由后续正式业务接口管理。
- 订单、购物车结算、积分、优惠券和地址页面当前尚未实现，本次只提供守卫与草稿接口，不新增假业务页。现有 `layout needLogin` 可作为展示保护，但不能代替页面请求前的守卫或后端鉴权。

## 环境与联调

前端参数：`VITE_ID` 对应后端小程序记录，`VITE_APP_ID` 对应微信 AppID，`VITE_API_PREFIX` 指向联调 API 根路径（含 `/api/min`）。必须核对三者一致。当前默认接口地址沿用本地 `http://visa.test/api/min`，环境变量可覆盖；发布前必须显式设置正式 HTTPS API 地址。

现有 app1/app2 使用同一个 AppID，仅 `VITE_ID` 为 1、2；配置未擅自修改。两个目标构建通过不代表两个真实微信应用已联调。正式 AppID 映射待确认。

示例（请替换为实际联调地址；真机不能使用电脑的 127.0.0.1）：

```sh
VITE_API_PREFIX=http://127.0.0.1:8000/api/min npm run dev:mp-weixin:app1
```

当前构建配置会修改 `src/manifest.json` 中的 AppID。本次验证前后保存并恢复文件，未覆盖已有配置。切换构建目标时检查产物 AppID 和源码差异。

后端完整接口、协议环境变量、迁移及回退说明见后端项目 `docs/mini-auth.md`。本次未修改业务环境变量、未执行正式注册或发券。

- `npm run test:auth`：19 项通过。直接测试 Pinia、请求模块和登录页 setup 逻辑，包括协议、拒绝、回调清理、网络失败、会话恢复、并发401、迟到响应及草稿隔离。
- 后端 `php vendor/bin/phpunit tests/Feature/MiniAuthTest.php`：17 项、114 个断言通过，使用 SQLite 内存数据库与模拟微信响应。
- app1/app2 微信目标均构建成功，验证原生手机号按钮、隐私同意按钮事件及新增页面注册。测试构建使用本地 API 地址，没有请求生产接口。
- 全量类型检查基线 52 个错误，改动后 17 个，剩余均为原有问题；未新增类型错误。遗留集中于 iconfont 类型、旧 collection/shop 接口类型和通用工具函数。
- 构建仍有原有材料模块类型导入提示、Browserslist 数据过期提示。
- 未验证：微信原生面板的真机展示、真实 code 兑换、微信后台权限/额度/隐私配置、正式服务协议内容、MySQL 多进程并发及生产部署。

建议真机验收顺序：游客浏览 → 协议阅读 → 拒绝授权 → 首次登录 → 退出 → 重复登录 → 原页面恢复 → 会话失效 → 另一小程序独立登录。拒绝和失败不能困住游客，任何恢复不得自动下单或支付。
