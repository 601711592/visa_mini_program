邀请记录、奖励规则及邀请方式仅保留已经确认的待上线页面；不建立邀请关系，不生成推荐码和海报。公司地址和坐标待配置，导航按钮禁用，不编造地点。

## 预览方式：必须显式开启

先确认本地工作区没有需要保护的未提交改动，再切换开发分支。不要直接覆盖当前工作区。

```sh
git status
git fetch origin
git switch feat/mall-static-pages-20260918
git pull --ff-only

# 浏览器前端预览；已有项目依赖时可直接运行
npm run dev:h5 -- --mode preview

# 微信开发者工具前端预览（与上条二选一）
npm run dev:mp-weixin -- --mode preview
```

首次安装依赖按项目现有 `yarn.lock` 执行 `yarn install --frozen-lockfile`，不升级框架、不重建锁文件。微信预览导入 `dist/dev/mp-weixin`。

`.env.preview` 显式设置 `VITE_MALL_PREVIEW=true`。该模式跳过真实会话初始化、正式协议获取、原生手机号授权及商城接口读取，只使用本地演示数据。顶部显示“前端演示 · 不产生真实订单或支付”；长按提示条可切换游客/已登录态或重置，用于检查页面状态。也可按正常按需登录路径操作。

**普通 app1/app2 构建不会自动启用演示。** 普通模式保留已有真实商品读取及登录逻辑，但新订单、积分、券、地址业务接口尚未接入，因此显示明确待接入状态，不把假订单或假余额当真实业务数据。要验收本轮完整静态交互，请使用上述 `--mode preview`。

预览内存数据刷新后重置；请只输入测试姓名、证件和地址，不输入真实个人资料。当前未配置独立 preview AppID，不会擅自覆盖 app1/app2 配置。既有构建插件会按已配置 AppID 修改 `manifest.json`，切换构建前后需检查并保留原值。
