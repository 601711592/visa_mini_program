## 信息结构和交互

用户区 → 我的订单 → 积分、券、邀请三行权益 → 地址、地图两行服务 → 原生底部导航。

- 顶部用户区：登录后编辑资料；游客进入登录。
- 订单：查看全部和四个状态筛选；已补充同风格订单列表、详情、继续付款、取消及退款模拟页面。
- 积分左侧：明细和规则；右侧去使用：进入产品分类。
- 优惠券左侧：全部券列表；右侧去使用：进入未使用券列表，沿归档流程使用。已补充券详情及按适用范围过滤的商品页，实际门槛仍以结算为准。
- 邀请：展示邀请概览、邀请记录、奖励规则及邀请方式页，功能保持待上线状态，不虚构奖励或推荐码。仅设计纳入，不代表启动推荐业务实现。
- 地图：游客可访问；未配置地址时禁用导航，不虚构地点。
- 游客按需登录，登录恢复原目标，不自动提交订单或付款。

## 微信小程序重构适配

1. 页面内容尺寸按设计 1px → 1rpx。HTML 的 zoom 仅用于等比预览，不迁移到 uni-app。
2. 优先原生 navigationStyle: default、navigationBarBackgroundColor: #8AD0F9、navigationBarTextStyle: black；原生标题栏位于页面内容之外。HTML mini-nav 和 capsule 都是预览示意，不复制进小程序 WXML。
3. 若后续采用自定义导航，必须通过 wx.getWindowInfo() 和 wx.getMenuButtonBoundingClientRect() 计算状态栏、胶囊避让与导航高度；平台测量值单位为 px，不机械改成 rpx。
4. 保留现有三个 tabBar：首页、产品分类、我的，激活色 #164E70。使用原生 tabBar 时删除 HTML 底栏和对应占位；不要重复绘制。自定义底栏才处理 env(safe-area-inset-bottom)，内容需留足底栏高度。
5. 750 稿上的点击高度至少 88rpx（375 设备约 44px）；当前 pill 视觉高度 66rpx，重构时以外层 88rpx 点击区域承接。列表行和左侧详情区为独立点击区域，右侧按钮用 @tap.stop，禁止按钮嵌套。
6. 身份、余额、券数量从 Pinia 与接口读取；未登录显示登录提示，加载中不误显示 0；接口失败可重试。手机号脱敏，头像昵称自愿完善。
7. 页面拆分：ProfileHeader、OrderShortcuts、BenefitRow、ServiceList；颜色和间距统一 SCSS tokens，配置驱动入口。详情与使用分别定义 route/action。
8. 小程序采用 navigateTo 进入详情，switchTab 进入分类和首页；保存登录 pendingAction 后恢复，不复用 iframe、DOM、localStorage 或网页事件。
9. 正式图标从库导出本地 SVG/PNG，先验证微信真机 SVG 支持，必要时使用 @2x/@3x PNG；不将 lucide DOM 脚本带入小程序。
10. 检查 320、375、390、430 宽设备、长昵称、系统字体放大、刘海与底部安全区、游客/登录态。真实手机号、分享、地图与支付能力后续单独联调。

## 文件和预览

- personal-center.html / personal-center.css / personal-center.js：主页面与预览容器。
- subpages.js：同设计语言的个人中心子页面、内存演示数据及导航栈。
- tests/flows.cjs：DOM 交互回归检查，临时安装 jsdom 后运行。
- 子页面使用同一套 750 宽设计变量，详情页不展示底部主 tabBar，返回保留筛选状态。
- 首页、分类及商品详情仍复用归档 flow.html；结算生成的订单、积分余额、券使用状态与个人中心同步，均为内存模拟数据。
- flow.html：从归档 fragment 复制并增加预览桥接，未改归档源文件。
- 工具条只在浏览器中出现，不属于小程序设计。
- 所有资源本地化，可直接打开 HTML；建议通过本地 HTTP 预览。
- 本轮不修改现有 uni-app、后端和管理后台代码。
